# DAY 7
Push, pull, and sync are key operations when it comes to maneuvering between your local and remote repositories.

Like we have alluded to, the remote repository serves as our central point of collab. Local repositories give you the leeway to make alterations without necessarily impacting what everyone else is using. 

The star commands to achieve this synchrony are
`git pull`
`git push`

## Step1: Getting the contents of a remote repository
`git pull` is the command to run when you want to fetch and integrate changes on remote to your local repository. 

The changes made to your local repository can similarly be accomplished by `git fetch` then `git merge`. So why have a set of separate commands when you could simply sync your repositories with one?

Well, fetching is a safer, non-destructive way to update your knowledge of the remote state. It allows you to inspect  changes and decide how and when to integrate them, rather than letting Git decide automatically with `git pull`. 

Let's test it out.

On bash, run `git pull`. Your remote and local repositories should be in sync already with nothing to update. 

Go into your GitHub repositories where you created a repository for remotes. 

Create or upload a new .html file and add in this sample of a simple website.

<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <title>My First Webpage</title>
</head>
<body>
    <h1>Hello World</h1>
    <p>This is my webpage description.</p>
</body>
</html>

Save it and commit your changes. Now, other than the README.md in the root of this directory, you have a new html file. 

Run `git fetch` then `git merge`. 

Notice what happened. 

## Step2: Create and resolve a conflict
While still on GitHub, open the README.md and add a description for your html file e.g what it contains.

Then move back to your local repository, open the same README.md and add a different comment and save. 

Commit your local changes: `git commit -am "added conflicting description"`

Run `git pull`

You should see a merge conflict. You will have to fix the conflicts and commit your results. 

I prefer to open the file with the merge conflict with VS Code to resolve in merge editor. 

You can sync the repositories with the features on Source Control tab on vs code or simply run a push and pull to confirm you are up to date.
