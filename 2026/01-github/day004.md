# DAY 4 BRANCHING 
A branch in Git is a divergence from another branch (most commonly main).
Branching allows you to make changes based on the same commit history without affecting the original branch, main, until those changes are merged.
A branch is not a full copy of the codebase. Internally, it is a lightweight pointer to a specific commit. This pointer moves forward as new commits are added, allowing you to compartmentalize work safely.

Different projects require different branching strategies. In my case, I primarily use feature branching, which is often paired with pull requests to review and approve changes before merging into main. We will also explore the forking workflow later, where contributors create their own copy of a repository (with shared history) to propose changes without direct write access to the original project.

Now, back to branching basics.

## Step1: Create a new feature branch
First, check your status and list out all branches currently present in your repository.
`git status`
`git branch`

Create a new branch to test branching logic
`git checkout -b feature-branch`

This is shorthand for creating a new branch and switching to it. The longer version would be:
`git branch <branch-name>` then `git checkout <branch-name>` or `git switch <branch-name>`

Edit your notes file or create a short script, whichever you prefer and then check your working directory status.

Within your new branch’s working directory, you now have various untracked changes. Add them to your staging area and commit your changes to the local repository, still within this branch. 

What happened above? Your branch moved forward, but the main branch is still the same. 

Switch to the main branch.

Attempt to merge the new branch to main so all your changes are tracked in main. Use `git merge <branch-name>` here.

Now main is up to date. Run `git log --oneline --decorate` to view how git pointers changed when you created a new branch and merged to main. 

Delete the branch you created 
`git branch -d <branch-name>`

## Step2: Create and resolve a branching conflict

Just like in step1, create a new branch and switch to it.

Make some modifications while in this branch then commit your changes. E.g modify your noted file.

Ensure to successfully commit to your local repository. 

Switch back to main and make some modifications to the file as you did above. Commit these changes as well.

Now attempt to merge the new branch to the main branch. 

You will see a merging conflict arise.

Resolve the merge conflict in the file(s) I am on VS code so I used the interface.

I also had to re re-run `git commit` to conclude the conflicting merge.
