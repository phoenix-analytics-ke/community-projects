# DAY 6 PUSHING TO REMOTE REPOSITORIES
Working with a distributed version control system like Git requires a clear understanding of how remote repositories are managed, especially in collaborative workflows.

This section of the Git Book provides a clear and well-structured explanation of the core concepts behind remote repositories and how Git interacts with them:
https://git-scm.com/book/ms/v2/Git-Basics-Working-with-Remotes

The key objective for today is to understand how local and remote repositories operate independently, and how to safely reconcile differences between them when their histories diverge.

## Step1: Testing remote repositories from scratch
Create a new directory and maneuver into it to initialize git.
`mkdir remote-test`

`cd remote-test`

`git init `

Add a README.md file for this repository and add in a heading 
`echo "# Remote Repositories Breakdown" > README.md`

Check your status and then commit your new changes. 

Inspect the current remote repositories inside your directory, you shouldn't have any. 
`git remote -v`

You are fully working in your local repository like we did in the first couple of days. 

Add a new remote repository with
`git remote add origin <repository-url>`

The url should be built this way: `https://github.com/<your-username>/repository-name.git`

E.g. `https://github.com/Ae0nn/remote-test.git`

Rerun remote repos check command and see the difference in your output. 

Now refresh GitHub repositories from your end and voila... nothing.

You added a remote repository on CLI but it isn't available on GitHub. You need to create a repository on GitHub, with the same repository-name you used in your url above, in order to sync with your local repository, then run

`git push -u origin main`

P.S You will be required to authenticate git via a code or on browser to make changes to your GitHub account.
