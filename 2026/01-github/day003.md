## Step1: The core idea behind commits in Git
Every time you create a new commit, you effectively adding all the current contents of the index also known as staging area to the local repository. 

Core syntax for working across the 3 core git stages are the following: 
`git add`
`git status`
`git commit`
`git log`
`git diff`

## Step2: Experimenting with Commits
Open the notes file you created yesterday inside git-challenge directory and list down all the git commands you have learned so far. 
Run `git status` to inspect your state
Run `git diff` to view the changes between notes.md before and after modifications
At this point, if you run `git restore <file_name>` ALL changes in your working directory will be discarded. 
Add your changes to the staging area 
Run your commit command
`git commit –m “this is some test commit”`
If you run your `git diff` command returns nothing because git snapshots are up-to-date with the modifications made on notes.md
Run `git commit --amend` to modify the commit message to be clear, and descriptive of the changes made to the file, e.g 
`git commit –amend –m “Add list of current relevant git commands”`
**WARNING:** It’s better to amend commits when correcting recent mistakes, not commits already pushed to shared branches. More on this later. 
Run `git log` to share your commit history. You should see the most recent commit has a better commit message from the initial one.
