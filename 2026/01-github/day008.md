# DAY 8 REBASE & HISTORY CLEANUP
`git rebase`
Up till this point, we have been discussing how git stores a snapshot of your project state with each commit pointing said snapshot. In the event of anything, we can roll back to the point at which everything worked, or even attribute each commit to the individual who made it. 

Well, today we will be changing history… our commit history.

Using git rebase, you can reorganize recent commits by reordering them, editing commit messages, or squashing multiple commits into one. Rebase does not modify commits in place; instead, it recreates them with new commit hashes, effectively replacing the old history with a cleaner version. 

Before we move on, let’s touch on git references, specifically HEAD. HEAD points to the current location within your given branch i.e the current state of your files inside your git repository.

## Step2: Use git rebase

Clean up the sloppy commits we just created into one clean commit. 

If we wanted to amend the most recent commit we could simply use: 

`git commit --amend -m "Better commit message"`

But we want to restructure our 3 most recent commits in history. 

Use `git rebase -i HEAD~x`

x being the number of commits we want to “rebase”

For this use case we will be using squash to combine multiple commits into one. This article here is great guide to understanding what other ways we can alter commit logic: https://medium.com/@slamflipstrom/a-beginners-guide-to-squashing-commits-with-git-rebase-8185cf6e62ec

Run `git rebase -i HEAD~3`

An editor opens with your 3 most recent commits in ascending order, oldest to newest 

Modify the texts in front of the commits in this order:

-pick a85f005
-squash a29e010
-squash cdf02fb

Press escape and type out :wq to save the changes

You will be redirected to a new editor window to update your commit message 

Type out a relevant commit message then press escape and type out :wq to save the new commit message 

Run `git log –oneline` to view the modifications
